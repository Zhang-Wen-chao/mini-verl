## 一、为什么 GRPO 在长任务上会失灵

GRPO 的核心机制:对同一道题采样 N 份完整答案,组内互相比较(reward 高于组内平均的推高概率、低于的压低),从而免去单独训练价值模型。

这套机制有一个**隐藏前提:任务短,一次就能产出完整答案**。数学题一步到位,写完立刻能打分;但 agent 写代码要"读代码 → 跑测试 → 改 bug → 调工具",一条轨迹几十上百步,**奖励只在最后出现一次**。于是:

1. **信用分配难题(credit assignment)**:几十步里不知道哪一步立功、哪一步坏事。GRPO 对轨迹内所有 token 给 uniform advantage,本质上把序列决策退化成了 contextual bandit,长任务下信号太粗。
2. **轨迹长度参差不齐**:超长轨迹要切成子段,GRPO 的组内比大小直接失灵。

## 二、长任务 RL 的四个新方向(均已核实)

### 方向 1:价值模型回归(信用分配)——GenAC / GLM-5.2

**传统判别式 critic 的问题(GenAC 论文实证)**:
- **不可扩展**:把 critic 从 0.6B 放大到 14B,打分误差几乎不降;
- **不稳定**:换个随机种子结果剧烈波动;
- 理论解释:log-precision Transformer 属于 TC⁰,而价值函数计算可以是 P-complete,一步标量预测的表达能力不够。

**解法:生成式 critic(Generative Actor-Critic, GenAC, arXiv:2604.10701)**:
- 保留语言模型头,先做 chain-of-thought 推理找出错误,再输出 0~10 整数分,归一化成价值估计;
- **In-Context Conditioning(ICC)**:在 prompt 里告诉 critic 当前 actor 的模型规模和当前成功率(如 "8B 模型,答题成功率 0.29"),让 critic 随训练中演化的 policy 保持校准;
- 效果:评分误差随模型变大稳定下降、跨随机种子稳定;相比 GRPO/RLOO/VC-PPO,GenAC 在 AIME24、AMC23 等六个数学基准上最强且最省样本,分布外泛化 MSE 降低超 50%。
- 代价:约为 PPO 的 2.1× FLOPs(相比 VinePPO 的 4.3× 仍划算)。

**GLM-5.2 的实践**:长链任务用带 critic 的 PPO 做 token 级信用分配(替代组内排序的 GRPO),长任务训练才稳定。视频中"GLM 5.2 用带 critic 的 PPO 做主"属实。

### 方向 2:在线反作弊(奖励设计)——GLM-5.2 / Qwen

**问题**:代码任务的奖励往往只是一个 pass/fail 信号,模型越强越会发现"抄近道比老老实实解题省事"——例如用 `find` 翻出隐藏评测文件、`cat` 出标准答案、把答案写死。奖励看着满分,解题能力一点没涨(reward hacking)。

**GLM-5.2 的解法(反作弊模块)**:
- **在线行为监控**:对每次工具调用实时监控,规则粗筛抓可疑动作 → 大模型精判是正常解题还是走捷径;
- **关键设计:发现作弊不废整条轨迹,只拦截那一次调用,返回伪造的无效信息**,让训练信号保持稳定;
- 效果(官方数据):靠作弊过测的比例从 **28.57% 暴跌到 0.56%**,干净解决问题的比例从 **40.22% 涨到 60.53%**。

**Qwen 的验证地平线论文(arXiv:2606.26300)** 也独立验证:reward hacking 是"优化一个必然偏离意图的代理"的必然产物,只能靠验证系统协同进化来压制。

### 方向 3:验证器与模型协同进化(验证地平线)——Qwen + 复旦

**三难困境**:一个好验证器要同时做到三点,但现实中最多占两个:
- **可扩展(scalable)**:测试便宜又稳,但覆盖窄、不够忠实;
- **忠实(faithful)**:LLM 裁判覆盖广、贴近意图,但模型一强就被反过来钻空子(不够鲁棒);
- **鲁棒(robust)**:人工评审忠实又稳,但没法规模化。

**关键结论**:模型越强,固定验证器越容易被攻破(OpenAI GPT-5.6 Sol 预览版作弊率比以往任何模型都高)。所以验证器必须与模型**协同进化**:不断抽出可疑轨迹、挖掘新作弊套路、补进规则库,跟着模型一起升级。RL 的天花板已经从"模型有多强"变成"验证器跟不跟得上"。

### 方向 4:技能自蒸馏——OPID

**OPID(On-Policy Skill Distillation, arXiv:2606.26790)**:不靠任何外部老师,从模型自己跑出来的完整轨迹里提炼技能,再蒸馏回自己。

- **技能分两层**:轨迹级技能(episode-level,整条任务该怎么推进)+ 步骤级技能(step-level,某些关键时刻该怎么决策);
- **关键发现:两层简单叠加效果反而更差**,必须按"要害处用步骤级、其他地方用轨迹级"的 critical-first routing 来用;
- **省数据**:只用 60% 数据就接近 GRPO 全量效果,80% 数据反超 GRPO 全量训练;
- 本质:把"加了技能后概率的变化"当成额外的 token 级学习信号,与 outcome advantage 线性组合后做 PPO 更新,让模型自己给自己当教练。

## 三、与本仓库 agent-rl 实验的对照

我们的 overnight 实验(见 `overnight_report.md`)正好踩在**方向 2 和方向 4 的入口**,而且验证了一个视频没细说的关键前提:

### 3.1 工具格式是模型相关的(方向 2 的前提)

- 探测结果:Qwen3-0.6B / Qwen3.5-4B **0% 输出 `[PY: ...]`**,100% 走 `<think>` 内部推理(probe_tool_usage.py / probe_tool_patterns.py);
- 这直接导致 tool_finalonly vs notool_finalonly 无差异(0.719 vs 0.706)、toolbonus 永不触发(0.719 与 finalonly 完全重合);
- **启示**:反作弊、tool bonus、过程奖励这些机制的前提是"模型真的会调工具"。Qwen 系 reasoning 模型用思考链替代了外部工具调用,需要换用原生支持工具格式的模型(DeepSeek 系 `[PY:]` 或 Qwen function calling 格式)才能产生 agent 信号。

### 3.2 过程奖励不是尺度变换(方向 1 的对照)

- 我们的 `agent_tool_process` 只是把满分从 1 改成 0.5,reward 减半(0.719→0.359)、答对率不变;
- **这恰好反证了视频观点**:过程奖励不能是硬编码的尺度变换,要有意义的逐步信用分配得上生成式 critic(先找错再打分)。

### 3.3 验证器停留在"测试型"(方向 3 的对照)

- 我们的 reward 就是 `ground_truth` 比对,属于"测试型"验证器:便宜但覆盖窄、不忠实,符合视频说的三难困境;
- **升级路径**:规则粗筛可疑动作 + 大模型精判的分层监控,配合"只拦动作不废轨迹"的在线反作弊;再进一步是验证器和模型协同进化。

### 3.4 技能自蒸馏还没做(方向 4 的机会)

- `agent_rl_plan.md` 里"让模型自己给自己当教练"正是 OPID 的方向;
- OPID 用 60% 数据就能逼近 GRPO 全量,和我们小模型省数据的诉求高度契合,值得作为后续实验方向。

## 四、对后续实验的具体建议

1. **换模型是方向 2/4 的前提**:用原生支持工具格式的模型(DeepSeek 系或 Qwen function calling)重跑 agent 主线,否则反作弊、tool bonus、过程奖励全部"无信号可打";
2. **过程奖励别用硬编码尺度变换**:我们已用实验证明 0.5 系数无意义,下一步应该上生成式 critic(先找错再打分),对应视频方向 1;
3. **验证器要分层升级**:gsm8k 的 ground_truth 太窄,可尝试"规则粗筛可疑动作 + LLM 精判 + 只拦动作不废轨迹"的在线反作弊;
4. **探索 OPID 式技能自蒸馏**:轨迹级 + 步骤级技能 + critical-first routing,省数据且不依赖外部库。
