# GRPO 算法动画拆解（视频笔记）

> 来源：B 站「耿直哥」——《【大模型 强化学习】GRPO算法，什么鸟玩意儿？》
> 本文是根据视频中文字幕整理的学习笔记，保留动画讲解的叙事顺序，修正了语音识别的错别字。

---

## 1. 开场问题

- 为什么 GRPO 能助力 **DeepSeek** 在性价比上远超 OpenAI 的 PPO？
- 既然它这么好，为什么在**游戏/具身智能**领域却没有推广？
- GRPO 有何奥秘、有哪些局限、预示强化学习什么未来？

## 2. 基础概念串讲（动画）

- 神经网络估计策略函数：输入 `s_t`（状态，如游戏中角色位置/速度），输出 `a_t`（动作，如左移/跳跃）。
- `p(a_t|s_t)` = 给定状态选择动作的条件概率。
- **监督学习 vs 强化学习**：
  - 监督学习：外部给静态数据，直接喂模型训练；
  - 强化学习：与环境互动中自己教自己——先用旧策略输出动作施加给环境产生新状态，再迭代策略。
- 因此必须**控制更新幅度**：变化太快容易学出问题。

## 3. PPO 回顾（GRPO 的对比基准）

- PPO 用**比值 r_t** 衡量新旧策略变化，clip 函数进一步限定更新幅度，保证稳定。
- 在语言生成场景：常用查询 Q 替换状态 S，用输出变量 O 替换动作 A（字母对应关系容易混乱）。
- 目标函数"看着长"，本质 = **比值 r_t × 优势 A_t**（控制迭代幅度 + 考虑具体动作打分）+ clip 裁剪。
- 期望 E 表示对多条数据取平均；求和符号是对同条数据内多个时间步求平均。
- 动画直觉：更新策略 π_θ 就是在参数空间不断迭代上升找最优 `θ*`。用策略比值做标准，局部优势 A_t 相当于**坡度**（决定前进还是后撤），clip 限定搜索区域——**小步快跑**。

## 4. 新问题：PPO 的瓶颈

- **优势函数 A_t 的计算十分复杂**：
  1. 根据输出 O 经奖励模型生成 R；
  2. 借助**价值网络（Critic）**生成 V；
  3. 用 **GAE** 算法计算 A。
- 大模型场景下价值网络非常大 → **训练难、很费钱**。

## 5. GRPO 的两个核心改进

> GRPO 本质上只做了两个改进：

### 改进一：去掉价值网络

- 优势 A 不再来自"价值网络 + GAE 算法"。
- 一次性输出多个 O，生成对应奖励 R，然后**用组内相对值**计算 A：
  ```
  A_i = (r_i − 组平均) / 组标准差
  ```
- 显著降低推理时的**内存占用和时间开销**——简单粗暴、便宜好用。

### 改进二：step-level → solution-level

| | PPO | GRPO |
|---|---|---|
| 采样 | 一个 prompt 输出一个序列 | 一个 prompt 输出多个完整序列 |
| 优势计算 | 每个 **token** 算一次 A（step level） | 每个**序列**只算一次 A（solution level） |
| 关心什么 | 这个词写得好不好 | 整段回答好不好 |
| 平均方式 | 先 token 层求平均，再样本层平均（涉及概率分布，用期望 E 表达） | 组内做一次平均即可（不涉及概率分布） |

### KL 正则项的区别

- KL 正则**不是 GRPO 的本质创新**（PPO 也有），差别在**位置和功能**：
  - PPO：**逐词约束**（per-token KL）
  - GRPO：**整段约束**（sequence-level KL）

## 6. 为什么 GRPO 适合 LLM、不适合游戏/机器人

- **NLP 任务 = 爬粗犷的石头山**：
  - 输出评价以段落为基准（"大石头"），无需小心翼翼搜索；
  - 免除价值网络、几个方向同时大步试、选最好的即可；
  - 这就是 GRPO 用**稀疏奖励 + 组内宽松打分**效果反而更好的原因。
- **游戏/机器人控制 = 在冰川上走路**：
  - 每步都要非常小心，一步错损失巨大；
  - 外部奖励**密集**、需要细腻优化 → 这种高精度控制 **PPO 更擅长**。

## 7. 一句话总结

> GRPO = PPO 的"去价值网络 + 组内相对优势 + 整段级约束"改造，专为大模型（数学/代码等稀疏奖励、段落级评价）任务设计；代价是失去了细粒度、密集奖励场景的精度。
