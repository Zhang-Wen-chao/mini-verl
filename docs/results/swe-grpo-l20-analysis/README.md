# SWE-GRPO 复现包：负结果文档里每个数字是怎么算出来的

配套文档：[SWE-GRPO on 2×L20：一次可判定但没有迁移的 agentic RL 实验](../swe-grpo-l20-negative-result.md)

## 为什么要有这个目录

那份结果文档里的每一个数（797 组、39.8%/46.0%/14.2%、44/55、13.9%→48.8%、
以及「去重会把曲线抬高 3.5pp」）都是**从 200 个 rollout dump 逐条重算**的，
不是抄二手汇总。但只写结论、不给脚本，等于**要求读者相信作者自己算的东西** ——
而这份实验最核心的一条教训恰恰是：**自己算出来的比率不能自证**。

所以这里把当时用的脚本原样放出来（只把写死的私有路径改成环境变量）。
第三方拿同一批 dump 应当能重跑出同一批数。

## 输入：dump 的形状

训练器每步落一个 `rollout_<i>.pt`（torch pickle），关键字段：

```python
{
  "rollout_id": int,                 # 第几次 rollout（本实验 0..199）
  "samples": [                        # 注意：这个列表里有条目级重复，见下
      {"label": "django__django-11099",   # 题 ID
       "index": 16,                        # 样本序号
       "reward": 0.0,                      # 规则判分：0 或 1
       ...},
      ...
  ],
}
```

- 用 `torch.load(p, map_location="cpu", weights_only=False)` 读（pickle，需要 torch）。
- **dump 本身不随仓库分发**（本实验 646 MB，且是集群内产物）。只要能拿到这五个字段，
  脚本就能跑；字段名若变，改脚本里的取值即可。

跑法（三个环境变量，无需改脚本）：

```bash
export SWE_DUMPS=<内含 rollout_*.pt 的目录>
export SWE_LOGS=<训练主日志>:<attempt1.log>:<attempt2.log>   # 只有 roll_compare.py 需要
for f in learnband learnband2 diag_groups dedup_curve roll_compare; do
  python3 "$f.py"
done
```

## 五个脚本各回答什么

| 脚本 | 回答的问题 | 需要的输入 |
|---|---|---|
| `learnband.py` | 训练池里哪些题**真的贡献了梯度**？组一级/题一级的可学带 | `SWE_DUMPS` |
| `learnband2.py` | 难度分层长什么样？「已经会了」的题占多少？**为什么是 797 组不是 800**？ | `SWE_DUMPS` |
| `diag_groups.py` | 为什么组内样本数不都是 8？重复的规模与形态 | `SWE_DUMPS` |
| `dedup_curve.py` | 重复是「同一采样的副本」还是「两次不同采样」？原样 vs 去重的曲线差多少？ | `SWE_DUMPS` |
| `roll_compare.py` | **裁决者**：训练器自己吃的批次是「原样」还是「去重」？ | `SWE_DUMPS` + `SWE_LOGS` |

## 实测期望输出（重跑时应能对上）

### `learnband.py`

```text
dump 数 = 200   (rollout,题) 组数 = 797   题数 = 55
A. 组一级:  全败 317 (39.8%)   混合(有梯度) 367 (46.0%)   全胜 113 (14.2%)
B. 题一级:  出现过混合组(可学带) 44 题 (80.0%)   从未成功 11 题 (20.0%)
D.              11/55 题 = 20.0%
```

### `learnband2.py`

```text
每个 rollout 含几道题:  4 道的 197 个,  3 道的 3 个
      ⇒ 797 = 197×4 + 3×3  —— 「200×4=800」的差就出在这 3 个 rollout 上
按总体通过率分层(55 题):
  0%(从未成功) 11   0~10% 4   10~30% 13   30~70% 13   70~90% 7   90~100% 7
「已经会了」(≥90%) 7/55 = 13%;它们参与的组数 82/797
```

### `diag_groups.py`

```text
组内样本数直方图: 只有 218 组是 8 个样本,其余从 9 一直到 54
index 有重复的组: 578 个,重复 index 共 3759 个
样本数>8 的组里,不同 index 数仍恒为 8   ⇒ 重复的是「同一 index」,不是多采了样本
```

### `dedup_curve.py`

```text
重复 index 的奖励是否一致:  一致(纯副本) 6400 对   不一致 0 对
20 步桶(原样/去重):  0-19 13.88%/17.50%  …  160-179 48.78%/55.78%  180-199 39.37%/48.59%
50 步桶(按 rollout_id // 50 真切):  0-49 19.75%  50-99 28.83%  100-149 38.34%  150-199 44.21%
```

去重后每个 20 步桶都**恰好** 640 = 20×4×8，与声明的协议逐字吻合 ——
这正是「去重看起来更干净」的来源，也正是它骗人的地方（见下）。

### `roll_compare.py`（决定性的一步）

```text
训练器自报 raw_reward 的 rollout 数 = 61
原样 与训练器的平均差 = -0.31%   绝对差均值 = 0.31%     ← 60/61 逐点一致
去重 与训练器的平均差 = +3.52%   绝对差均值 = 4.54%     ← 系统性偏高
```

⇒ **那些「重复」就是训练器真正吃进去的批次。** 去重会把整条曲线整体抬高约 3.5pp，
**而曲线形状照样单调、照样好看** —— 没有任何内部信号提示它错了。

## 用这个包时的四个坑（都是实测踩过的）

1. **不要顺手去重。** dump 的 `samples` 里有字面重复，形态上完全像纯副本
   （6400 对全一致、去重后桶容量恰好等于协议值）。**裁决只能用 `roll_compare.py`** ——
   拿被分析系统**之外**、但同源的数（训练器自己日志里的 `rollout/raw_reward`）逐点对照。
   不要只比桶均值：均值会互相抵消出假吻合。
2. **离群先查自己的取数谱系。** `roll_compare.py` 的 rollout 10 会显示
   训练器 35.59% vs dump 16.98% 的离群。这**不是 dump 的缺陷**：那 61 个 `raw_reward`
   来自三段不同的 run —— attempt1 覆盖 0–9、attempt2 只有 10、主日志 50–99。
3. **20 步桶和 50 步桶不能混着凑。** 20 步桶起点是 0/20/40/60…，取 (0,20,40) 实际覆盖
   **0–59**，标签却是 0–49。50 步聚合必须按 `rollout_id // 50` 直接切。
4. **torch 不在宿主机上。** 本实验的 dump 只能在有 torch 的容器里读
   （`nerdctl exec <容器> python3 ...`）。

## 附：`preflight_steplimit.sh`

不是分析脚本，是**发车前置断言**：动作预算 `SWE_AGENT_STEP_LIMIT < 40` 且未显式声明
冒烟（`SWE_ALLOW_SMOKE=1`）就拒绝启动；空值、非纯正整数同样拒绝。
它来自那次「冒烟档的 15 步静默漏进生产、整轮评测跑在 15 步上」的事故
（见结果文档「四处静默失效」①）。

三种取值实测：

```bash
bash preflight_steplimit.sh 15      # ⛔ 拒绝发车(exit 1)
SWE_ALLOW_SMOKE=1 bash ... 15       # ⚠️ 按冒烟放行(exit 0)
bash preflight_steplimit.sh 40      # ✅ 放行(exit 0)
```
