# Qwen3.5-4B PPO vs standard GRPO：公平开发对照契约

状态：等待外部 GPU 作业释放后，先串行执行 PPO 5-step，成功后执行同契约的 standard GRPO
5-step。只有两腿都通过稳定性门，才推进到 20-step 开发对照。

## 为什么不是直接比较旧运行

刚通过的 PPO 1-step 只使用每步 3 条 trajectory；已有 GRPO 开发运行使用每步 3 prompts times
4 rollouts，即 12 条 trajectory。直接比较二者会把 rollout 数不同误写成算法效果。本对照从同一
Qwen3.5-4B base checkpoint 重新开始，固定每步 3 prompts times 4 rollouts，共 12 trajectories。

## 两种公平性，分开报告

PPO 额外训练 4B Critic，故不可能同时让更新数、rollout 数与 GPU-hours 全部相同。项目将回答
两个不同问题：

1. **固定样本预算（当前）**：两边相同的 prompts、rollouts、长度上限、数据顺序、seed 和
   3 trainer + 1 rollout 拓扑。它衡量同样训练信号下的开发变化、稳定性和样本效率，同时如实
   报告 PPO 的额外时间/显存成本。
2. **固定计算预算（后续）**：用当前测得的每-step GPU 时间，缩短较慢算法使总 GPU-hours
   相等。它衡量同样成本下的效率，不能取代固定样本预算的结论。

由于从第二步起两种策略已不同，无法也不应强行让生成 token 完全相同；改为固定完成次数和
token 上限，并记录每腿的实际 total tokens 与 step time。

## 冻结的 5-step / 20-step 契约

| 变量 | PPO | standard GRPO | 说明 |
|---|---:|---:|---|
| Base model / train rows | Qwen3.5-4B / 相同 2037 OpenR1-Math rows | 相同 | 不从旧 checkpoint resume |
| Seed / 数据顺序 | 42 / shuffle=False | 相同 | 固定 actor、data loader、rollout seed |
| 拓扑 | 3 FSDP2 Actor + 1 TP=1 vLLM | 相同 | PPO Critic 为 pinned entrypoint 所要求的 FSDP1 |
| 每步训练信号 | 3 prompts times 4 rollouts = 12 trajectories | 相同 | 两腿最重要的共同预算 |
| 长度上限 | prompt 512 / response 384 / model 896 | 相同 | 既有非退化 reward 的短回答契约 |
| Actor LR / KL / sampling | 1e-6 / 0.001 / temperature 0.8, top-p 0.95 | 相同 | Critic LR=1e-5 仅 PPO 所需 |
| Advantage | GAE, gamma=1, lambda=1 | group relative reward, std normalization=true | 唯一算法性差异；PPO 另有 value Critic |
| 开发评测 | 相同 MATH 64，训练前与最终各一次 | 相同 | 仅开发遥测，不能作为最终算法胜负 |

验收要求：每一步均有训练指标，最终 checkpoint 和 rollout JSONL 必须存在，actor loss/KL
必须有限；PPO 额外要求 value loss、values、advantages 有限。任何 OOM、NCCL、NaN 或 Inf
都使该腿停止，不进入 20-step。

## 解释边界

5-step 只确认放大到四个 rollout 后两侧都稳定；20-step 的 64 题变化只用于判断是否值得更长
实验。已有 MATH held-out 200 已被过去 679-step GRPO 读取，不能在本短开发对照中反复读取后
再称为全新 final。选择算法或超参数前需要另行固定新的 development/final split，并以多 seed
在共享 final 协议下报告质量。

运行器 [await_fair_algorithm_comparison.sh](../../await_fair_algorithm_comparison.sh) 只会在四张
GPU 均空闲时启动，不会终止或修改外部进程。
