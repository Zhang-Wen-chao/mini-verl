# Qwen3.5-4B PPO/GAE actor--critic：1-step 可行性校准

日期：2026-08-22。状态：**已通过真实 4×L20 PPO/GAE 1-step gate；尚未进行 PPO 与 GRPO 的质量比较。**

本记录回答的不是“PPO 是否优于 GRPO”，而是一个先决问题：在现有 4×L20、锁定的 official
verl revision c4b389a 和 Qwen3.5-4B 上，真实 actor--critic PPO 能否完成一轮 GAE 更新，以及
最小一步的资源成本是多少。

## 成本与资源观测

训练核心 step 的 timing_s/step=92.27s，其中 rollout 生成约 7.02s、reference log-prob
15.47s、Critic update 19.77s、Actor update 22.16s、rollout weight sync 24.09s。首次端到端
运行总时约 388s，含 Ray/vLLM/模型初始化、CUDA graph capture、一次 64 题验证和 checkpoint
保存；checkpoint 保存本身约 59.16s，因此不能把 388s 外推为稳定训练的每步时间。

训练日志中 Actor/Critic 最大 allocated 显存均为 31.15GB、reserved 37.91GB；运行期间
nvidia-smi 观测三张 trainer 卡约 25--41GB、rollout 卡约 37.4GB，均未 OOM。完整产物约
134GB，主要来自 3-way FSDP 的 Actor/Critic model 与 optimizer checkpoint；这是首个成功
actor--critic 证据，当前保留，不应为节省空间而删除。

## 修复的 pinned-upstream 接口边界

本次没有改写锁定的 official verl snapshot；所有修复在本仓库的运行时兼容层中：

1. experimental one-step Critic factory 仅接受 critic.strategy=fsdp，并从
   critic.model.fsdp_config 读取 engine 参数；因此 Critic 是 FSDP1，Actor 保持 FSDP2。
2. FSDPCriticModelCfg 只继承 BaseModelConfig，未执行 HFModelConfig 的 post-init；FSDP engine
   随后访问 hf_config、local_path、processor 时会失败。
3. 新增 FSDPCriticHFModelConfig，继承官方 HFModelConfig 来真实加载 Qwen config/tokenizer，只
   额外携带 fsdp_config。CPU-only preflight 已验证它得到 Qwen3_5Config 与 Qwen3VLProcessor，
   不加载权重也不占用 GPU。
4. pinned OneStepOffRayTrainer 对 standalone Critic 调用了不存在的 init_model() RPC；兼容层按
   同 revision 的 SeparateRayPPOTrainer 改为注册的 reset() 并设置 value_loss。Actor/Ref/RM
   逻辑未改变。
