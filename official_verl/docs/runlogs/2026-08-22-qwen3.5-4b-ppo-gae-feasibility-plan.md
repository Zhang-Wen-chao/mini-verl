# Qwen3.5-4B PPO/GAE actor--critic：可行性校准记录

日期：2026-08-22。状态：**未启动 4B PPO；被运行时 CUDA 兼容性阻断。**

这不是 PPO 与 GRPO 的质量比较。目标只是回答一个更基础的问题：在现有的 4×L20、
官方 `verl` 和 Qwen3.5-4B 上，真实 actor--critic PPO 是否能完成一轮有意义的 GAE 更新，
以及每轮的时间/显存成本。

## 已准备的受控首测

启动器：[run_qwen3_5_4b_ppo_gae_calibration.sh](../../run_qwen3_5_4b_ppo_gae_calibration.sh)；
守门及验收器：[await_ppo_gae_calibration.sh](../../await_ppo_gae_calibration.sh)。

固定契约如下：

| 项目 | 值 | 原因 |
|---|---|---|
| 模型 / reward / prompt | 与当前 4B GRPO 相同 | 仅测 PPO Critic/GAE 可行性，不混入任务变量 |
| 算法 | `algorithm.adv_estimator=gae`，`gamma=1`，`lam=1` | 真正走 GAE，而非伪装成 PPO 的 GRPO |
| Critic | 同一 Qwen3.5-4B checkpoint，FSDP2、gradient checkpointing、参数和 optimizer offload | PPO 的 value model 必须实际加载与更新 |
| 拓扑 | 3 trainer GPU + 1 vLLM rollout GPU | 与成功的 4B GRPO 运行一致 |
| 首轮工作量 | 1 step，batch=3，rollout_n=1 | `3 × 1` 是 3 trainer GPU 的最小可整除配置；用于生存性与成本，不用于质量比较 |
| 序列上限 | prompt 512、response 384、model 896 | 沿用已经有非退化 reward 信号的短回答契约 |
| 保存位置 | `/mnt/storage01/.../artifacts/` | 根盘仅约 31 GiB 可用；持久盘还有约 2.1 TiB |

成功不等于进程退出 0。守门脚本还要求 step 1 日志中出现并且为有限数：
`critic/vf_loss`、`critic/values/mean`、`critic/advantages/mean`、`actor/loss`、`actor/ppo_kl`，
并要求 `global_step_1` checkpoint、至少一个 rollout 样本，以及没有 OOM/NCCL/NaN/Inf。
如果这些条件有一项缺失，结论是“PPO 未被验证”，而不是“PPO 可行”。

## 当前阻塞的可复现证据

L20 当前 NVIDIA driver 为 `550.127.05`，其 runtime 上报 CUDA `12.4`。现有成功 GRPO
遗留的 official-verl venv 是 `torch 2.11.0+cu130`。在当前宿主直接探测时：

```text
torch: 2.11.0+cu130
torch.version.cuda: 13.0
torch.cuda.device_count(): 4
torch.cuda.is_available(): false
CUDA initialization: driver too old (found version 12040)
```

机器上未找到 CUDA forward-compat `compat/` 库；因此不应将这个 venv 直接用于真实 PPO。
此前 GRPO 的成功日志来自一个当时可用、之后已退出的 CUDA 容器上下文；历史成功不能证明
今天的宿主 runtime 仍能启动。另有外部 HNSW 作业在四张 GPU 上各占约 2.7 GiB；启动器
会在任何 GPU compute process 存在时拒绝启动，绝不终止或改变外部作业。

## 恢复条件与下一步

需要一个与 driver 550/CUDA 12.4 兼容、且包含官方 pinned `verl`、FSDP2、vLLM 的运行时。
恢复方式应由拥有机器环境权限的人选择，例如恢复此前带 CUDA forward compatibility 的容器，
或以 CUDA 12.4 兼容的 pinned 依赖重新构建独立 venv/container。**不要为了这次校准在共享机
上直接升级 NVIDIA driver。**

恢复 runtime 后，先运行这个 1-step gate；只有它通过，才按 5 step → 20 step 的顺序测稳定性
与 GPU-hours。170-step PPO vs GRPO 对照不在当前阶段启动。
